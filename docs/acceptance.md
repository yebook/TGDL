# 部署后验收

`scripts/acceptance.py` 用于检查已经运行的服务，支持 Python 3.10 及以上，仅使用标准库。可从 Windows 电脑或 NAS/Linux 运行，不需要安装后端依赖。它不启动容器，不初始化管理员，不修改设置，不操作下载任务，也不发送 Telegram 消息。

## 服务检查

在项目根目录运行：

```sh
python scripts/acceptance.py
python scripts/acceptance.py --base-url http://192.168.1.10:8000 --json
```

默认地址为 `http://127.0.0.1:8000`，单个请求超时 10 秒；可使用 `--timeout 30` 调整。地址必须是 HTTP/HTTPS 根地址，不接受 URL 中的用户名、密码、查询参数或子路径。不跟随 HTTP 重定向，也不使用运行环境中的 HTTP 代理；HTTPS 使用系统证书验证。反向代理应直接提供正确的 HTTPS 地址。

匿名模式检查 `/health/live`、`/health/ready` 和管理员是否已经初始化。未提供登录凭据时，管理接口明确标为 `skipped`。未初始化不会触发初始化操作，只会报告 `not_initialized`。

## 管理接口检查

```sh
python scripts/acceptance.py --base-url http://192.168.1.10:8000 --login --json
```

交互终端会询问管理员用户名及密码，密码输入不回显。不接受命令行密码，避免写入命令历史和进程参数。自动化可在本地受控环境设置 `TGD_ACCEPTANCE_USERNAME` 和 `TGD_ACCEPTANCE_PASSWORD`；不要将真实密码填入聊天、提交到仓库或输出到日志。没有完整凭据且无法交互输入时，退出码为 2，不发起网络请求。

内网 HTTP 与产品 WebUI 的访问方式一致，凭据会通过所选连接传输；在不可信网络中使用 HTTPS。脚本不会额外要求允许内网 HTTP 的开关。

认证模式创建一次临时登录会话，随后仅查询任务首页、设置与系统状态接口（用于顶部状态摘要），最后退出该会话。除登录和退出外不发送写请求。若网络中断导致退出失败，会记录失败；会话按服务端到期时间失效。脚本不复用或退出浏览器的会话。

## 结果如何理解

退出码：`0` 表示所选 API 检查通过，`1` 表示至少一项检查失败，`2` 表示参数或凭据输入错误。匿名模式可以返回 0，但认证接口仍未验证。`--json` 输出有固定 `schema_version`，包含检查时间、通过/失败/跳过、固定错误码和少量数值证据，不包含服务地址、用户名、密码、Cookie、CSRF、任务名称、目录路径或原始错误内容。

系统检查报告 Bot/代理状态、可用存储根数量、队列数量及恢复阻塞数量。`system` 通过表示接口结构可读取；即使 Bot 未配置、代理失败或目录不可用，也应依据这些证据进一步处理，不能理解为下载已可用。

**API 健康检查不证明真实媒体下载成功。** 输出始终列出尚未由脚本验证的真实 Telegram 媒体、大于 20 MB 视频、NAS 文件系统、代理 Telegram 路由和容器重建持久化。完整验收范围见 [验证记录](verification.md)。

部署后仍需在专用测试环境人工执行：

1. 配置 Bot、用户白名单和目标目录；转发真实大于 20 MB 的视频，检查确认前未下载、确认后结果与本地文件一致。
2. 转发图片和视频组成的媒体组，确认同目录归档及逐文件结果。
3. 检查默认全局并发 3、取消/失败重试、重启恢复及重复文件跳过。
4. 在 Docker 宿主机检查 UID/GID、目录写权限、挂载失效后不写入替代路径、重建容器保留配置。
5. 代理部署还需实测 HTTP CONNECT/SOCKS5、认证和 DNS、代理失效后不能绕过直连。

将实际设备、镜像版本、时间和观察结果补充到验证记录；不将模拟测试当作实机通过。

## 脚本自测

```sh
python -m unittest discover -s scripts/tests -p test_acceptance.py -v
```

这些测试使用本机临时 HTTP 服务，验证成功/失败、会话清理、重定向拒绝、超时、输入校验和输出脱敏，不连接 Telegram。
