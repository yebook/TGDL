# 配置备份与恢复

在 **设置 → 配置备份与恢复** 导出配置，使用独立备份密码加密；更换设备或重新部署后，在同一位置选择备份文件、输入密码、预览并确认恢复。

## 包含哪些内容

备份包含可编辑的平台配置：Bot Token、允许使用的 Telegram 用户 ID、API 模式、API ID / Hash、代理及代理密码、下载偏好、确认提示和文件名模板、时区与日志清理策略。导出的是**已经保存的配置**，未保存的表单修改不在其中。

备份文件使用密码加密，密码与管理员登录密码独立，不会保存到平台。密码至少 6 个字符，最多 128 个字符。请分别妥善保存文件和密码，密码丢失无法恢复；不要把二者一起公开。

部署环境固定的配置不会被导出，恢复时也不会覆盖目标环境的固定值；页面会列出跳过的字段。挂载路径、容器端口、UID/GID、Compose 和 `.env` 需要在新设备上单独配置。备份中的下载目录标识必须在目标部署中存在。

## 不包含哪些内容

**这不是整个平台的数据备份。** 不包含管理员账号和登录会话、任务和下载历史、数据库、媒体文件、诊断日志、本地 API 缓存，以及服务运行状态、请求冷却和安全保护状态。恢复配置不会复制或删除这些内容，也不会把旧设备的连接状态标记为已连接。

只想迁移配置时，先在新设备部署并完成管理员初始化，再导入配置即可。旧设备应停止使用同一个 Bot，避免重复消费者。恢复 API 模式和连接参数后，后台仍按正常流程应用配置、协调安全切换，保存成功不等于连接成功；请查看 API 与 Bot 状态。

## 恢复步骤

1. 打开设置中的配置备份与恢复，选择加密文件并输入备份密码。
2. 预览配置概要、包含的字段及跳过项；预览不会连接 Telegram，也不会修改配置。
3. 确认覆盖当前平台配置。若期间另一个会话修改了设置，请重新读取并预览。
4. 查看恢复结果与服务状态；如有需要，手动校验连接。

错误密码、损坏或不支持的文件、无效配置不会部分写入。恢复的是备份中的配置，包括空的密钥字段；请确认后再操作。导入不会更改管理员登录密码。

需要保留任务、媒体及 API 缓存时，仍需使用停服后的一致性完整备份，见 [运维与故障处理](operations.md#备份与恢复)。两种备份用途不同。
