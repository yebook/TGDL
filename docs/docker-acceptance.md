# Docker 隔离验收

无需 Telegram API 凭据，可以先检查生产应用镜像的初始化、管理功能与数据保留。
此工具会启动临时容器、创建临时管理员并修改临时配置；与只读的
[`acceptance.py`](acceptance.md) 服务检查职责不同。

## 执行

先启动 Docker Engine，并构建当前源码的应用镜像：

```text
docker build -t tgd-app-source:0.1.1 .
python scripts/docker_acceptance.py --run
```

Python 3.10 及以上即可，脚本仅使用标准库。可用 `--image` 指定已构建的本地生产镜像；
不自动拉取镜像。必须显式传入 `--run` 才会创建资源。
Windows Docker Desktop 需切换 Linux 容器。

脚本在系统临时目录创建独立数据、下载和缓存目录，容器名包含随机标识，
Web 端口由 Docker 动态分配且只绑定 `127.0.0.1`。不读取 `.env`，
不使用已有部署的管理员、配置或媒体，不启动 Bot API，也不访问 Telegram。
应用使用镜像默认生产入口、UID/GID `1000:1000`、只读根文件系统、
移除 capabilities 与禁止提权；备份复制和清理也由该 UID 执行，兼容 Linux 文件属主。
为允许容器 UID 写入，只有本次专用的临时目录设置为 `0777`，结束后清理。
生产目录应按部署指南设置实际 UID/GID 所有权与权限，不应照搬此临时权限。

## 检查内容

- 健康检查、生产 WebUI 页面及构建后的本地静态资源。
- 生成的初始化密钥创建临时管理员；初始化拒绝 5 位和 21 位密码，接受 6 位。
- 登录后携带 CSRF 与当前配置版本保存确认时限、并发数，Bot Token 保持为空。
- 修改密码拒绝 5 位和 21 位且保留旧密码；接受 20 位和 6 位，旧会话随之失效。
- 停止并重建容器，确认管理员、配置版本、配置内容和存储可用状态保留。
- 停服后完整复制数据（含数据库、主密钥、存储身份）、下载目录和缓存目录，
  先验证副本一致，再明确登记独立恢复目录并启动、重新登录、检查配置和存储。一个固定小文件仅用于检查字节保留，
  不表示实际媒体下载成功。

备份与恢复目录位于同一临时父目录，保持同一宿主文件系统与相同容器挂载路径。
工具先验证复制后的身份文件原样保留；由于复制目录的 inode 不同，再仅移除明确指定的临时恢复目录的身份记录，由应用重新登记。原目录的身份记录不变；这一步模拟经过确认的迁移，不是自动绕过运行中的存储检查。
此检查不覆盖跨文件系统/跨设备恢复；实际迁移时应遵循[维护指南](operations.md)，
设备或目录身份不一致会阻止存储，需按[下载目录身份登记](upgrade.md#storage-identity-011)确认并重新登记。

## 输出与清理

标准错误输出固定阶段进度，标准输出为 `schema_version: 1` 的脱敏 JSON；
成功退出码为 `0`，缺少 Docker、镜像或任一步失败为 `1`，参数错误为 `2`。
不输出随机密码、初始化密钥、Cookie、CSRF、API 原文或 Docker 错误原文。
缺少环境不会伪装为通过，也不会自动改用测试服务。

脚本结束（含检查失败和 Ctrl+C）会清理本次随机命名的容器与临时目录。
如果 Docker 本身失联导致清理失败，会明确返回失败；恢复 Docker 后，
可在 Docker 管理界面核对并删除本次 `tgd-smoke-` 容器，再清理对应的
`tgd-docker-smoke-` 系统临时目录。不会按此前缀批量删除其他运行资源。

通过此检查仍不代表真实 Telegram、大于 20 MB 下载、真实代理、Docker 宿主机
权限或 NAS 文件系统已验收；这些项目继续在[验证记录](verification.md)中单独跟踪。
