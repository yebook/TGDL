# 自定义 Bot 提示与文件名

在 WebUI「设置 → 提示与命名」修改模板，即可查看使用演示数据的示例。点击「保存设置」后生效，保存无需连接 Telegram。「恢复默认提示」「恢复默认文件名」只修改当前表单，仍需保存。

Bot 通知首行显示消息类型，第二行显示完整任务编号，之后才是正文。确认正文保持原有模板，已有自定义模板不会被覆盖。

模板用于新生成的 Bot 确认卡。已有卡片、已确认任务和重试继续使用原计划，不会因修改模板而重命名。确认、取消按钮始终由系统提供。

任务标题优先使用[转发前指定的名称](usage.md#转发时指定名称)，其次使用媒体消息的文字摘要；无文字时使用原文件名或媒体类型。同组文件采用首条非空文字，标题最长 80 字。任务列表与 Bot 提示会单独显示完整任务编号，无需将编号写入模板。

单文件保存到 `YYYY-MM-DD/`，媒体组保存到日期下以任务标题命名的目录。同名组目录使用 `名称 (2)`、`名称 (3)` 依次区分，不覆盖已有文件。目录结构见 [任务与归档](usage.md#目录与命名)；下方模板只控制文件名。

## Bot 确认提示

支持直接换行，长度为 1–2000 个字符，不能全为空白。默认：

```text
======
📥 确认下载：{title}
📄 文件数量：{file_count} 个
📦 总文件大小：{total_size}
📁 保存到：{destination}
⏳ 确认有效期：{expires_in_minutes} 分钟
======
{files}
```

消息类型和完整任务编号由系统显示在上述模板内容之前，不需要写入模板：

```text
📋 等待确认
任务编号：e5f6a7b80123456789abcdef01234567

======
📥 确认下载：海边日落
…
```

`======` 用于分隔概要与文件清单。默认概要包含文件数量和总大小，任何文件大小未知时总大小显示“未知”。

| 变量 | 内容 |
| --- | --- |
| `{title}` | 任务标题：指定名称优先，否则为消息文字摘要（无文字时为原文件名或媒体类型）；不追加编号，与 WebUI 一致 |
| `{file_count}` | 文件数量 |
| `{total_size}` | 总大小，使用 KB、MB、GB 等单位；大小不全时显示未知 |
| `{files}` | 计划保存的文件清单：每项显示“文件名”和独立一行的“文件大小”，多文件之间空一行 |
| `{destination}` | 保存目录 |
| `{expires_in_minutes}` | 确认有效期，单位为分钟；非整分钟最多显示两位小数 |

例如：

```text
准备下载 {file_count} 个文件，共 {total_size}
{files}
保存目录：{destination}
请在 {expires_in_minutes} 分钟内确认。
```

确认有效期在「设置 → 下载与保存」以分钟配置，默认 30 分钟，可设 0.5–1440 分钟。提示模板使用 `{expires_in_minutes}` 并标注“分钟”。修改设置只影响后续确认卡，已发卡片的到期时间保持不变。

`{files}` 的显示示例（大小未知时显示“未知”）：

```text
文件名：海边日落.mp4
文件大小：12.5 MB

文件名：海边日落.jpg
文件大小：未知
```

文件大小的分行样式自动用于后续生成的确认卡，包括使用 `{files}` 的自定义模板，无需恢复默认提示；已发出的消息保持不变。

## 入队与结果通知

手动下载依次收到确认、入队和结果通知。启用自动下载时跳过确认，只发送入队和结果。入队表示任务已交由系统按并发设置处理，不代表所有文件已经开始传输。

入队通知显示任务标题、数量、类型构成、总大小、保存目录，以及每个文件的计划名称和大小。例如：

```text
⏳ 已加入下载队列
任务编号：e5f6a7b80123456789abcdef01234567

海边旅行

3 个文件 · 共 16.0 MB
视频 × 1 · 图片 × 1 · 文件 × 1
保存目录：2026-11-02/海边旅行

下载清单
1. 海边日落.mp4 · 12.5 MB
2. 海边合照.jpg · 2.4 MB
3. 行程安排.pdf · 1.1 MB

系统将按并发设置处理，完成后通知你。
```

结果通知按实际情况显示“✅ 下载完成”“⚠️ 部分下载完成”“❌ 下载失败”“🛑 下载已取消”或“📁 文件已存在”，区分新下载、已存在、失败和取消的数量，列出文件结果和实际保存位置。有可靠保存记录时显示已保存大小；失败文件显示可操作的原因和建议。

大小未知时显示“未知”。文件清单过长时会提示省略数量，并保留任务编号、概要和关键处理建议。新展示用于后续生成的通知，已生成的通知和历史消息保持原样。

## 保存文件名

只控制文件名，不改变单文件或同组多文件的归档目录。长度为 1–160 个字符，不能全为空白；不要填写路径或扩展名，系统自动保留安全原扩展名。普通附件原名本来没有后缀时保持无后缀；原名缺失时根据已知 MIME 或 Telegram 类型补充，无法确定则使用 `.bin`。默认 `{name}`，不附加任务编号、文件 ID 或固定序号。

| 变量 | 内容 |
| --- | --- |
| `{name}` | 优先使用转发前暂存的指定名称，否则为原文件名主体；原名缺失时为消息标题，再无标题则自动命名 |
| `{date}` | 收件日期，格式 YYYYMMDD |
| `{time}` | 收件时间，格式 HHMMSS |
| `{datetime}` | 收件日期时间，格式 YYYYMMDD_HHMMSS |
| `{type}` | `video`、`image`、`audio`、`voice`、`animation`、`video_note` 或 `document` |
| `{index}` | 可选：同一请求中的文件顺序，从 1 开始；仅主动加入模板时使用 |
| `{id}` | 可选：文件短 ID；仅主动加入模板时使用 |

“设置 → 提示与命名”中的“消息标题最大长度”默认为 20，可设置为 1–80 个字符，超长时末尾的 `…` 计入长度。自动任务标题与原文件名缺失时采用的消息标题同步遵守此限制，文件扩展名独立保留；原文件名和手动指定名称沿用原有规则。修改仅影响新生成的计划，已有冻结任务及重试路径保持不变。

“遇到换行截断标题”默认开启：先取消息第一行，再按上述长度限制截取；关闭后，将各行合并为空格再截取。文件名缺失时采用的消息标题也同步使用该规则。第一行为空时按原有规则选择其他有效组成员或回退名称，不取同条消息的第二行。

日期、时间使用请求创建时刻及设置中的归档时区，并非媒体拍摄时间。示例使用一条原名为 `海边日落.mp4` 的演示视频：

| 模板 | 文件名示例 |
| --- | --- |
| `{name}` | `海边日落.mp4` |
| `{date}_{name}` | `20261020_海边日落.mp4` |
| `{date}_{type}_{index}` | `20261020_video_1.mp4` |

没有原文件名时优先用消息标题命名。同组所有文件共用按消息顺序取得的首条非空文字；标题内的点号不会当作原文件扩展名。无原名且无标题时按类型兜底，例如 `video.mp4`、`image.jpg`、`voice.ogg`；未知附件使用 `document.bin`，已知 PDF MIME 可使用 `document.pdf`。扩展名仅用于命名，不代表对文件内容进行了校验或转换。

只有完整文件名重复时才追加 `_2`、`_3` 等数字，不按文件数量统一加序号。例如同组的 `旅行.jpg` 与 `旅行.mp4` 不重名，各自保持原样；三个同名视频则保存为 `旅行.mp4`、`旅行_2.mp4`、`旅行_3.mp4`。单个文件通常无需序号；若保存目录已经有同名文件或其他任务已预留名称，也会追加数字，避免覆盖。名称比较不区分大小写。

文件名会清理不支持的字符，过长时缩短并保留扩展名。确认卡生成时预留计划名称；确认后若外部程序新建同名文件，保存时仍以数字后缀避让，并在结果中显示实际路径。已确认任务和重试保留原计划，不会自动重命名已有文件。

已保存的文件名模板保持不变。如当前模板仍有 `{id}` 或 `{index}`，请点击「恢复默认文件名」并保存，后续新任务即可使用无编号的默认命名；主动使用这些变量的自定义模板仍按配置执行。

两类模板均只支持表内变量。需要显示文字花括号时，连续输入两个左花括号和两个右花括号，例如下面的输入显示为 `{name}`：

```text
{{name}}
```

未知变量、错误括号、表达式和文件名中的路径或非法字符会阻止保存，并保留当前输入供修改。
