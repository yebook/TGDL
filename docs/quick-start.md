# 第一次下载

目标是先下载一个小文件，确认 Bot、网络和保存目录都能正常使用。先选择云端模式，无需申请 API ID / Hash。

## 1. 安装并打开 WebUI

尚未部署时，先按 [Docker 部署指南](deployment.md) 准备完整源码、目录与权限，再构建启动。部署只使用根目录的 `compose.yaml`，无需另外准备代理配置文件。

默认 WebUI 地址是 `http://127.0.0.1:8000`，仅部署主机可访问。其他设备通过内网访问须将 `.env` 中的 `TGD_BIND_IP` 改为部署主机的固定局域网 IP，再访问该地址。Windows 本机操作见 [本地运行](local-run.md)。

首次打开时，从应用数据目录读取 `bootstrap.key`（默认 `data/bootstrap.key`），创建管理员账号和 **6–20 位密码**。初始化密钥只用于首次设置，不要上传、截图或发送到聊天。

## 2. 连接自己的 Bot

通过官方 `@BotFather` 创建专属 Bot，准备 Bot Token 和自己账号的数字 Telegram 用户 ID。在 **设置 → 连接 Telegram**：

1. 填写 Bot Token 和允许使用的用户 ID，选择官方云端。
2. 无法直连 Telegram 时启用代理，填写容器可访问的 HTTP CONNECT / SOCKS5 地址与端口。电脑的系统或浏览器代理不会自动应用到容器，见 [代理说明](telegram-api.md#本地-api-也需要代理时)。
3. 点击「保存设置」，再按需点击「校验配置」。保存不要求在线，校验不会替代保存。
4. 查看顶部状态及本分区的连接提示，确认 Telegram 中聊天对象与配置的 Bot 一致。向 Bot 发送 `/start`，检查是否回复。

同一个 Bot 只能由一个程序接收消息。先停止其他使用此 Token 的程序。若页面显示限流、认证暂停或切换中，按提示等待或处理，勿反复提交。

## 3. 发送媒体并确认

发送或转发一个 **小于 20 MB** 的视频或图片给 Bot，发送的是实际媒体消息，不是 `t.me` 链接。

Bot 会返回文件信息、目标目录和「确认下载」「取消」按钮。核对后点击「确认下载」。默认需在 **30 分钟**内确认；过期后重新发送媒体即可。

## 4. 检查结果

在 **下载任务** 打开任务详情，观察进度及逐文件结果。完成后检查下载目录中的实际文件和 Bot 的成功反馈。通知发送失败与媒体保存失败不同，先核实文件结果，不要重复下载。

单文件直接保存到 `YYYY-MM-DD/` 日期目录，同组多文件在日期下新建组目录。最顶部与账户位于同一顶栏持续显示连接、活动与等待文件数和剩余空间；具体保存位置在「设置 → 下载与保存」查看，有异常可前往对应设置处理。

## 接下来

- 下载超过 20 MB 的视频：[获取 API ID / Hash 并切换本地 API](telegram-api.md)。本地服务可响应仍需通过实际收发消息验证 Telegram 连接。
- 调整下载位置、确认期限、并发及日志：[设置怎么用](settings.md)。
- 理解同组媒体、目录和删除记录：[任务、进度与归档](usage.md)。
- 保留配置或排查故障：[配置备份](configuration-backup.md) · [常见问题](faq.md)。
