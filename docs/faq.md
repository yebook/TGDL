# 常见问题

## 云端 API 需要 API ID / Hash 吗？

不需要。云端使用 Bot Token，下载上限 20 MB。大文件使用本地官方 Bot API，才需要 API ID / Hash。两种模式都使用同一个 WebUI，详见 [接入指南](telegram-api.md)。

## 保存成功，为什么仍未连接？

保存只检查字段并持久化。查看顶部状态摘要，再到「设置 → 连接 Telegram」检查代理应用状态、请求等待时间和 API 切换步骤；需要时手动校验。网络错误、进程运行和真实下载成功是不同状态。

## 显示“本地 API 可用”，但 `/start` 没回复？

该状态表示本地服务能响应，不能保证它与 Telegram 的上游连接正常。先确认聊天对象、白名单和请求保护状态，再检查代理：Docker 不自动继承宿主机的系统或浏览器代理。请在 WebUI 填写容器可达的代理地址和端口，并允许 Docker 网络访问。项目不会自动发现宿主机代理；关闭代理则使用容器默认网络。详见 [本地 API 代理说明](telegram-api.md#本地-api-也需要代理时)。

## 本地 API 下载时为什么没有百分比？

项目配套构建的本地 API 支持真实下载字节进度；总大小准确时显示百分比，只知道估算大小时显示“约”，总大小未知时只显示实际已下载大小和可用速度。标准 Bot API 没有此接口，使用自定义外部服务或进度暂不可用时，会显示动态指示和耗时，下载仍继续。下载到 100% 后还需保存文件，不代表任务已完成，见 [进度说明](usage.md#下载进度)。

## 找不到初始化密钥？

首次启动会在配置的应用数据目录生成 `bootstrap.key`，默认是项目下 `data/bootstrap.key`。已初始化后用管理员密码登录。不要在日志、问题报告中粘贴密钥。

## 其他设备打不开 WebUI？

使用 `http://部署主机IP:8000` 访问；修改了 `TGD_WEB_PORT` 时使用对应端口。无需额外设置绑定地址；若无法打开，检查容器运行状态、发布端口和宿主防火墙。容器里 `127.0.0.1` 指该容器，不能用来连接宿主机代理。参见 [部署指南](deployment.md)。

## 账号风险与异常处理 {#account-risk}

::: danger Bot 和个人账号都可能受影响
**Bot 可能被 Telegram 限流、限制或封禁；关联的 Bot 所有者个人账号也可能受限、被封禁或无法登录。** 接入前请评估能否接受这一风险。云端 API、本地 API、代理和项目的请求保护都不能保证账号不受限制。
:::

具体限制原因和处理结果由 Telegram 决定。仅凭 Bot 断连、显示“已销号用户”、个人账号退出登录，或两者先后发生，无法确认触发原因，也不能据此认定是某次下载、文件大小或 API 模式导致。`429` 通常表示请求限流，`401` 表示认证失败；网络超时也不等于封禁。

项目只使用 Bot Token 操作机器人，不登录个人账号，不保存个人账号登录会话。申请 API ID / Hash 时在官方网页登录，仅用于获取应用凭据；这两项凭据本身不能让项目读取你的个人账号消息。这些边界不代表 Bot 所有者的账号没有风险。

使用时尽量控制不必要的请求：

- 仅供自己或明确授权的用户使用，配置允许使用的用户 ID，避免公开提供下载服务或发送骚扰消息。
- 只处理自己有权保存、符合 Telegram 规则的媒体，遵守 [Telegram 服务条款](https://telegram.org/tos) 与 [Bot 开发者条款](https://telegram.org/tos/bot-developers)。
- 从少量文件开始，保持合理并发；看到限流按提示等待，不反复校验、重启或切换 API 试探恢复。项目的节流、退避和认证暂停只减少无效调用，不能作为安全保证，见 [请求保护](operations.md#telegram-请求等待与认证暂停)。

发现 Bot 疑似被封或个人账号异常时，先暂停使用与自动尝试，保留发生时间、错误码和脱敏诊断日志。不要公开 Token、API Hash、登录码或媒体原文件。核实 Telegram 官方客户端提示，并通过客户端提供的申诉入口或 [Telegram 官方支持](https://telegram.org/support) 寻求处理；处理方式和能否恢复以官方回复为准。

## 清理诊断日志会删除文件吗？

不会。「设置 → 维护与备份」的日志清理只处理诊断事件，不改变媒体、任务、配置、凭据、API 缓存或请求冷却。清理后继续写入新日志；完整策略见 [日志说明](operations.md#持久诊断日志)。

## 本地下载会一直占两份空间吗？

下载和保存期间，API 缓存与最终文件会暂时各占一份。标准部署在最终文件完整保存后自动清理对应媒体缓存，保留 API 运行数据。清理需要等待同一批活动下载结束；失败会独立重试，不影响已保存文件。不要手动剪切或清空整个 API 目录，详见 [缓存维护](operations.md#api-缓存维护)。

## 能下载消息链接、绕过保护或自动扫描频道吗？

目前不能。只处理白名单用户实际发送/转发给 Bot 的媒体，不登录个人账号，不监听频道。仅保存自己有权处理的内容。
