# 设置怎么用

设置按使用流程分为四个分区。先完成「连接 Telegram」，其他设置可以保持默认，开始第一次下载后再调整。切换分区不会清空正在填写的内容。

## 连接 Telegram

1. 填写专属 **Bot Token** 和允许使用的 **Telegram 用户 ID**。用户 ID 是自己账号的数字 ID，不是手机号或 `@用户名`。
2. 选择 API 模式：先用**官方云端**，只需 Bot Token，下载上限 **20 MB**；需要大文件时，选择**本地 API** 并填写 API ID / Hash，见 [获取凭据与切换步骤](telegram-api.md)。
3. 网络不能直连 Telegram 时，启用代理并填写容器能访问的地址。云端与本地使用同一份代理设置；关闭代理时使用容器默认出口，不会自动读取电脑的系统或浏览器代理。详见 [代理设置](telegram-api.md#本地-api-也需要代理时)。
4. 点击「保存设置」。保存无需连接 Telegram；「校验配置」用于检查当前填写的连接参数，并不替代保存。

保存成功后，观察顶部连接提示及本分区的切换进度。「本地 API 可用」只代表本地服务可以响应，并不证明 Telegram 消息能实际收发；请发送 `/start` 并测试媒体下载。不要让其他程序同时使用这个 Bot 接收消息。

API 或代理连接修改一旦受理，Bot Token、API 模式、API ID / Hash 和代理输入会暂时锁定，直到本次操作结束；请等待结果，不要连续保存不同连接方案。允许使用的用户 ID、下载、命名和日志设置仍可调整并保存。失败后可按原因修正连接配置或手动重试；退出结果不明确时仍需按页面说明明确确认，不会自动重复退出。

若另一会话已开始切换，而当前表单还留有尚未保存的连接修改，页面会保留这些输入；期间保存只提交其他设置，连接部分需等操作结束后再保存，以页面提示为准。

本分区也提供连接重试、本地 API 状态和符合条件时的重启、恢复操作，无需开启调试。出现限流、认证暂停或退出结果不确定时，先按页面提示处理，勿反复切换模式或重启绕过等待。

### 一直等待或无法继续编辑时

- **状态更新失败**：使用「重新同步状态」。这会重新检查已保存配置和后台进度，保留正在填写的内容，不会再次提交保存。保存请求超时也先同步，确认结果后再操作。
- **连接操作失败**：修正连接配置后保存，或使用「重试操作／重试连接」。重试使用已保存配置，未保存的修改仍留在表单中。
- **等待下载结束**：正常下载不会因切换超时被中断。到下载任务页查看进度，必要时取消任务，待安全结束后继续。
- **冷却等待或退出结果不确定**：按页面说明等待或核实；重新同步、重试和重启都不能跳过这些保护。

若重新同步也无法访问应用，检查 Docker 中应用及本地 API 服务是否运行。必要时重启应用容器后再次查看状态；不要删除数据目录或修改数据库解锁。云端退出过程中重启仍可能需要明确确认退出状态，重启不表示操作已成功。

## 下载与保存

| 设置 | 怎么选 |
| --- | --- |
| 保存位置 | 选择已挂载且可写的下载目录；宿主机实际路径在部署环境中配置 |
| 确认有效期 | 默认 **30 分钟**；过期后重新发送媒体给 Bot |
| 同时下载文件数 | 默认 **3**；网络或磁盘吃紧时调低，按文件计数而非任务组数 |
| 重试与时区 | 按需调整；归档日期、模板时间与每日日志清理使用设置的时区 |

这里可查看下载目录与 API 缓存的空间状态。大文件需要同时预留缓存和目标目录的空间；顶部剩余空间摘要不能代替检查所有存储位置。

单文件直接保存到日期目录，同组文件在日期下使用消息标题建立一个组目录，不附加任务编号；重名时追加 ` (2)`、` (3)`，不覆盖已有内容。完整结构见 [任务与归档](usage.md#目录与命名)。

## 提示与命名

不需要自定义时保持默认即可。需要调整时，编辑 Bot 确认提示或文件名模板，查看示例，保存后用于新任务。恢复默认只修改表单，还需保存。

完整任务编号由系统单独展示，无需手动加进标题。模板只处理普通文本，不执行代码；文件名不要填写目录或扩展名。变量和示例见 [模板指南](templates.md)。

## 维护与备份

- **配置备份与恢复**：用独立密码加密备份已保存的配置与可编辑密钥。不会备份任务、管理员账号、数据库或媒体，详见 [备份范围](configuration-backup.md)。
- **诊断日志**：查看当前占用、导出最近事件或确认后手动清理。默认保留 **7 天**，每天应用时区 **08:00** 清理，可修改时间或关闭按天清理，容量上限仍生效。
- **显示调试详情**：位于「开发者选项」，默认关闭，仅当前登录会话生效。需要排障时开启以查看配置来源、修订、进程和操作标识等细节；不会增加 Telegram 请求、改变日志级别或显示保存的密钥。

日常查看日志、备份、重试连接及重启本地 API 不依赖调试开关。故障处理见 [维护指南](operations.md)。

## 保存、校验与顶部状态

「保存设置」保存各分区的修改，保存结果以消息提示显示；切换 API 或代理的实际应用可能稍后完成。密钥输入框留空表示保留已保存的值，清除要使用对应的明确操作。环境固定的字段只能在部署环境中修改，页面会说明只读原因。

API 类型与状态、当前 Bot 用户名与状态、代理状态、下载队列和剩余空间显示在最顶部，与账户操作位于同一顶栏。API 切换时会显示目标类型；「可响应」表示 API 能处理请求，「Bot 已就绪」表示应用已建立 Bot 客户端，实际收发仍需发送消息确认。空间摘要只显示可用容量，具体保存位置在「下载与保存」查看。「直连」表示未启用应用代理，「代理已应用」表示配置已生效，不代表 Telegram 一定连通。异常或等待优先提示，连接详情在「连接 Telegram」。状态刷新失败时，原结果不代表当前仍正常，请刷新或检查应用连接。

应用版本显示在桌面导航栏左下角，手机位于导航底部，可查看对应更新日志；不会自动升级应用。页面不再重复显示当前页面标题，使用侧边导航和设置分区定位即可。

若提示配置被其他会话修改，保留自己的输入，重新读取最新设置后核对再保存；不要通过连续提交覆盖他人修改。离开未保存的设置时，先按提示保存或放弃。
