# 验证范围与边界

本页描述检查覆盖范围，不把模拟测试、容器启动或健康接口当作真实 Telegram 下载验收。具体变更采用与影响范围匹配的定向回归；可重复命令见 [开发指南](development.md)。

| 层次 | 已有本地检查覆盖 | 仍需注意 |
| --- | --- | --- |
| 后端单元 / 集成 | 请求聚合、确认、取消、去重、文件安全发布、任务删除、模板、模式切换、请求保护、诊断日志 | 使用假 Telegram 与临时存储；Windows 会跳过部分 POSIX 权限检查 |
| Linux 隔离检查 | 非 root、受限权限、日志与进程管理边界 | 不连接真实 Telegram，不挂载用户数据 |
| 前端 / 浏览器 | 表单保存与冲突、任务操作、完整编号、滚动稳定、桌面/手机布局、管理状态及日志导出 | 自动测试环境与真实 NAS 浏览器环境不同 |
| Docker 应用 | 源码镜像构建、无凭据启动、健康检查、初始化、持久化、同文件系统停服备份恢复 | 不证明 Telegram 网络或 API 大文件链路正常 |
| 本地 API 管理组件 | 官方源码镜像构建、无凭据等待、心跳、隔离进程控制 | 进程运行不等于 Bot 已连接，更不等于媒体已保存 |
| 配置备份 | 加密往返、错误密码与损坏文件拒绝、环境固定字段跳过、版本冲突、不同实例密钥下恢复配置及密钥 | 不包含业务数据；真实 NAS 跨设备迁移仍需实机验收 |
| 原生代理传输 | 实际 C++ 镜像在断网容器中，通过 SOCKS5 / HTTP CONNECT 拒绝、同缓存关闭代理、无效配置与缺少模式共五项系统调用检查 | 不使用真实凭据，不证明真实代理认证或 Telegram 连通；重现命令见开发指南 |
| 原生下载进度 | 固定版本源码实际编译；生产缓存的别名、容量、保留和重试检查，以及缺少已有客户端时合法/异常输入均不创建客户端、无对外连接 | 断网合成检查未覆盖真实已授权客户端的 TDLib 下载事件；真实字节与速度仍待验收 |
| 本地下载进度展示 | 单元测试及桌面/手机真实页面自动刷新，覆盖实测零字节、准确/估算/未知总大小、进度不可用、下载完成待保存、阶段切换与取消 | 使用隔离合成进度；不证明真实 Telegram 的下载字节、速度或大文件行为 |

## 真实环境待验收

- 本地 Bot API 下载超过 20 MB 的真实视频，并核对保存字节与 Bot 结果。
- 观察真实本地下载的字节增长、速度、缓存命中及下载到保存阶段切换，确认最终文件成功前不会被提前标记完成。
- 混合多文件、迟到成员、重启聚合和逐文件结果。
- HTTP CONNECT / SOCKS5 认证、DNS、失败不直连与网络恢复。
- 飞牛 OS 的 UID/GID、共享目录 ACL、缺盘、空间不足和原子文件发布。
- 取消、崩溃和本地 API 后台获取的不确定状态与恢复。
- API 缓存维护、峰值空间与目标 CPU 架构。
- 跨设备备份恢复、生产升级与回滚演练。

请在专用测试目录与有权保存的媒体上验证。真实凭据只在部署环境输入，测试报告不包含 Token、API Hash、个人资料或原始媒体。日志可辅助建立启用后的故障时间线，不能补回未记录的历史，也不能确定 Telegram 内部审核原因。
