# 任务、确认与归档

将实际文件或同组多文件发送/转发给专属 Bot。转发频道的附件消息通常携带文件；只发送 `t.me` 链接不在支持范围内。受频道保护而无法转发的内容不能靠本项目绕过限制。

## 支持的文件

| 输入 | 支持范围 |
| --- | --- |
| 图片、视频 | Telegram 原生照片/视频，以及以附件发送的图片、视频 |
| 音频与动画 | 音频、语音、GIF/动画、视频留言 |
| 普通附件 | APK、PDF、ZIP/7Z/RAR、Office、文本等文件 |
| 未知类型 | 未识别的扩展名、无扩展名或没有原文件名的附件 |

普通附件不受扩展名白名单限制；无法识别分类时显示“文件”，仍可确认下载。文件原样保存，不安装 APK、不执行程序、不解压或转换内容。贴纸、联系人、位置和消息链接暂不支持。

## 确认与结果

Bot 汇总文件数量、可读大小和目标目录，提供「确认下载」「取消」。默认确认有效期 **30 分钟**，可在设置页调整；过期需重新发送文件。重复点击会按实际状态提示，不会重复创建下载。

确认后进入队列，全局默认同时下载 3 个文件；入队通知列出各文件的名称和大小，一组任务逐文件记录结果。Bot 和 WebUI 使用相同标题，Bot 通知首行显示消息类型，第二行单独显示完整任务编号，排障或区分同名任务时使用编号。启用自动下载后跳过确认，直接发送入队与结果通知。通知失败与文件保存失败分别记录。

每组任务结束后汇总反馈一次，区分已下载、已保存无需重复下载、失败及取消的文件数，并附文件清单；不会为组内每个成功文件分别发送成功通知。例如：

```text
✅ 下载完成
任务编号：完整任务编号

海边旅行

文件：2 个 · 已下载 2 个
实际已保存：2 / 2 个文件 · 共 14.9 MB
📁 实际目录：2026-10-28/海边旅行

保存结果：
✅ 日落.mp4
✅ 海岸.jpg
```

失败文件会附处理提示；部分成功时已保存文件会保留。重试结束后会再次汇总该任务的最新结果。

## 同组多文件如何合并

Telegram 会把同组媒体分别送达 Bot，图片与视频可能分批到达。属于同一 Bot、同一聊天、同一媒体组的文件会先收集，再生成一个任务和一张确认卡；例如同组的两张图片与三个视频会共同确认、归档到同一个组目录。单文件无需等待收集。

文档组、音频组也按 Telegram 提供的分组标识处理，界面统一称“文件组”。不同类型是否能由客户端组成一组取决于 Telegram；应用不会把分开发送的 APK、PDF 或其他附件自行合并。

收集至少等待 5 秒，并在最后一个新文件到达后再等待 3 秒，最多等待 15 秒。存在待处理消息时会在上限内延后确认卡。Telegram 没有提供“本组已全部送达”的结束通知，因此超过收集上限或确认卡已生成后才到达的成员会单独处理；已展示的卡片不会悄悄增加文件。不同媒体组或分开发送的文件不会仅因发送时间接近而合并。

## 下载进度

任务页自动刷新，逐文件展示当前阶段：

| 阶段 | 显示内容 |
| --- | --- |
| 配套本地 API 下载 | 实际已下载大小、可用的速度；总大小准确时显示百分比，估算总大小标注“约”，未知总大小不显示百分比 |
| 下载进度暂不可用 | 动态指示和耗时；不显示虚构的百分比，下载流程继续执行 |
| 云端流式下载 | 实际已下载大小、可用的速度；已知总大小时显示百分比 |
| 本地 API 下载完成后保存文件 | 实际已保存大小、可用的速度及百分比；这是缓存到目标目录的复制进度 |

本地下载进度来自项目配套构建的 API 服务，标准或自定义外部 API 可能不支持此能力。进度连接暂时中断时会显示“暂无法获取下载进度”，不会因此取消或重试下载。缓存命中可以直接显示下载完成；下载达到 100% 后仍需保存到目标目录，只有保存成功才算文件任务完成。

多文件任务显示已完成文件数；逐文件的下载或保存百分比不代表整组百分比。动态指示仅表示当前阶段仍在执行。

## 本地文件与删除任务

任务列表和详情会随自动刷新检查已保存文件。文件被手动删除或移走后，会显示本地文件缺失；一组只有部分文件缺失时，列表显示缺失数量，详情逐个标注。原来的下载成功结果仍保留。下载目录暂时不可访问时显示暂时无法检查，检查本身不会重新下载文件。

删除单个或批量已结束任务时，默认保留文件。需要同时删除文件时，在确认框中勾选「同时删除已下载文件」。其他未删除任务仍在使用的共享文件会保留，并在结果中提示；将相关任务一同删除时才允许删除该文件。下载、保存或取消尚未结束时，请先等处理完成。文件被替换或删除失败时，以操作结果为准，应用不会清空整个任务目录。

## 目录与命名

### 转发时指定名称

转发文件时，可以附带输入一条文字，例如 `海边旅行`；也可以先给 Bot 发送这个名称，再发送文件。同一用户、同一聊天发送的下一条文件或文件组会使用该名称，且只使用一次，不设有效期。Bot 不单独回复名称消息，直接在下载确认提示中展示最终名称。转发的纯文字消息和消息链接不会作为命名指令。

只有媒体尚未到达时，新文字才能替换暂存名称，发送 `/start`、`/help` 或 `/status` 才能清除它。媒体到达并使用名称后，再发文字会为下一条媒体暂存名称，不会修改当前任务或已生成的确认卡。若当前名称有误，请取消该任务，重新附带正确名称转发媒体。

指定名称优先于原文件名、原消息文字，用于任务标题、Bot 提示、组目录，以及文件名模板中的 `{name}`。例如指定 `海边旅行`，一组中的两个同类型视频保存为 `海边旅行.mp4` 和 `海边旅行_2.mp4`；单个视频无需序号。扩展名仍由媒体信息决定，名称中的路径字符会安全处理。

Telegram 的附带文字可能是独立消息，没有与转发媒体绑定的标记。本功能按接收顺序作用于下一条媒体或媒体组；请让文字先到达，并核对下载确认卡。一次转发多个不同媒体组时，名称只用于第一组。文字未先到达或没有附带文字时，均按下述现有规则命名，不修改已生成的确认卡。

```text
downloads/
└── 2026-10-21/
    ├── 单个视频.mp4
    ├── 单张图片.jpg
    └── 旅行片段/
        ├── 视频.mp4
        └── 图片.jpg
```

日期使用请求创建时间与设置时区，不是拍摄时间。任务名、组目录优先截取消息文字摘要，无文字时用原文件名或媒体描述。组目录只使用清理后的标题，不默认附加任务编号；同一天目录中名称冲突时依次使用 `旅行片段 (2)/`、`旅行片段 (3)/`，不覆盖或混入其他组的文件。

单个文件名由 [文件名模板](templates.md) 控制，默认不附加任务编号或文件 ID。原名缺失时优先使用消息标题，没有标题再按文件类型自动命名；同组共享标题，仅完整文件名重名时加 `_2`、`_3` 等数字，不同扩展名无需序号。没有额外的 `videos/`、`groups/` 分类层。修改模板不搬迁已有文件，也不改变已冻结任务或重试路径。已有带编号模板可在设置中恢复默认文件名并保存。

普通附件保留安全扩展名；原名本来没有扩展名时保持无扩展名。没有原文件名时，依据已知 MIME 或 Telegram 类型选择后缀，无法确定则使用 `.bin`。名称仍会清理路径字符并限制长度，避免越界或覆盖其他文件。

## 管理任务

任务页可按名称或完整编号搜索、按状态筛选并查看逐文件结果。页面自动更新进度，保留当前滚动与选择。失败项可按状态重试，成功文件不重复保存；取消获取阶段可能需要等待底层服务结束，见 [恢复说明](operations.md#获取阶段取消和重启恢复)。

已结束任务可单条删除或选择当前页多个任务批量删除。默认只移除记录展示，**保留媒体文件**；如需同时删除文件，请在确认框中勾选对应选项。活动任务先取消并等待结束；若批量中有不允许删除项，整批不执行。

## 设置保存

保存与在线校验分开：Bot Token、白名单可以先离线保存，后续手动校验。保存成功不等于 Bot 已连接；顶部显示连接概况，本地 API 的进程状态和切换步骤在「设置 → 连接 Telegram」查看。“本地 API 可用”表示本地服务能响应请求，Telegram 连通性仍需通过实际收发消息确认。不要让同一 Bot 同时被多个程序消费。
